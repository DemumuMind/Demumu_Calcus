# /eval Command System

## Overview

Система управления разработкой на основе оценок для Claude Code. Позволяет определять, проверять и отслеживать критерии качества функций.

## Установка

Система уже установлена в этом проекте:
- Скрипты: `.claude/scripts/eval.ps1`, `eval.bat`, `eval.sh`
- Оценки: `.claude/evals/`
- Реестр: `.claude/evals/_registry.md`

## Использование

### Создание оценки

```bash
eval define feature-auth
```

Создает файл `.claude/evals/feature-auth.md` с шаблоном. Заполните конкретные критерии.

### Проверка оценки

```bash
eval check feature-auth
```

Запускает интерактивную проверку всех критериев:
- Для каждого критерия спрашивает PASS/FAIL/SKIP
- Автоматически обновляет статус
- Логирует результаты

### Отчет

```bash
eval report feature-auth
```

Генерирует подробный отчет с метриками и сохраняет в файл.

### Список оценок

```bash
eval list
```

Показывает все оценки с текущим статусом.

### Очистка

```bash
eval clean
```

Удаляет старые логи (оставляет последние 10 записей).

## Структура файлов оценок

```markdown
## EVAL: feature-name
Created: 2024-01-15 10:30
Status: IN PROGRESS

### Описание
Авторизация пользователей через JWT

### Оценки возможностей (Capability Evals)
- [x] Пользователь может войти с валидными credentials
- [ ] Токен обновляется автоматически
- [ ] Ошибки авторизации логируются

### Оценки регрессии (Regression Evals)
- [x] Старые сессии продолжают работать
- [ ] Не ломается logout

### Критерии успеха
- pass@3 > 90% для оценок возможностей
- pass^3 = 100% для оценок регрессии

### Заметки
- Нужно добавить rate limiting
```

## Статусы

- **NOT STARTED** — оценка создана, но не проверялась
- **IN PROGRESS** — частично пройдена, требует доработки
- **READY** — все критерии пройдены
- **BLOCKED** — заблокирована внешними факторами

## Метрики

- **pass@1**: Процент успехов с первой попытки
- **pass@3**: Процент успехов с 3 попыток (для сложных задач)
- **pass^3**: 100% прохождение (обязательно для регрессии)

## Интеграция с разработкой

1. **Перед началом работы**: `eval define feature-name`
2. **Во время разработки**: `eval check feature-name` (частичные проверки)
3. **Перед PR**: `eval report feature-name` (финальный отчет)
4. **В PR**: приложить отчет `.claude/evals/feature-name-report-*.md`

## Пример рабочего процесса

```bash
# 1. Создаем оценку
eval define feature-search
# → Редактируем .claude/evals/feature-search.md

# 2. Проверяем начальное состояние
eval check feature-search
# → Все FAIL (ожидаемо)

# 3. Разрабатываем...
# ... пишем код ...

# 4. Проверяем прогресс
eval check feature-search
# → Часть PASS, часть FAIL

# 5. Продолжаем разработку...

# 6. Финальная проверка
eval check feature-search
# → Все PASS

# 7. Генерируем отчет
eval report feature-search
# → Статус: READY

# 8. Отправляем PR с отчетом
```
